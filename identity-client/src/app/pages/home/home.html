Sign in through your own identity server

A single-page app that hands sign-in to a custom .NET authorization server, using the Authorization Code flow with PKCE. It never sees the user's password. It only gets short-lived, scoped tokens.

PKCE for public clients

The server requires a code_challenge from clients without a secret, and checks the code_verifier before it issues tokens.

Consent & scopes

Users approve each scope (openid, profile, email), and the server remembers what they granted for each client.

Token lifecycle

Signed JWT access and ID tokens, one-time authorization codes, and refresh tokens that rotate on every use.
